# 项目接入闭环（0.1.11）

本文面向 ForgeRail 0.1.11，发布状态以 npm 和版本化 GitHub Release 为准。已发布 0.1.4 没有这些命令；安装 CLI 不会自动迁移旧快照，更新需明确授权。完整接口与恢复契约见 [英文说明](project-adoption.md)。

本轮只维护 ForgeRail 自身 Codex Skill 和 AGENTS 受管块；不管理第三方升级，不增加执行器或后台服务。目标项目不需要 package.json，CLI 本身仍需 Node.js 22+。

1. 用精确目标版本运行 `forgerail init --workspace <项目>`，获得只读计划。
2. Agent 展示差异，在用户已有接入授权内使用 `--apply <planSha256>` 执行，无须重复确认。摘要绑定内容，不代表批准。
3. 运行 `forgerail doctor --workspace <项目>`，离线检查来源与文件完整性。
4. 更新或移除分别使用 `update` / `remove`，同样先规划，再按摘要执行。

`.forgerail/config.json` 保存项目决定，`installation.json` 保存生成事实。目录存在不代表持久治理；不新增个人配置、父子自动合并或任务账本。整文件和受管块分别拥有；块外修改保留，块内或 Skill 漂移阻止覆盖/移除。移除不删除整个目录，也不卸载全局 CLI。

操作使用协作锁和临时恢复记录，安装清单最后写入。中断后用 `recover` 预览回退，再用 `--apply` 执行；目标出现外部修改就停止并保留。进程已退出的项目锁须按 doctor 给出的 lockDigest 单独释放。进程在单文件写入内部被杀死时可能留下锁或恢复副本，自动回退会拒绝，需要逐项核对，禁止批量删除恢复文件。

旧快照使用 `init --legacy-lock <docs下的来源锁>` 显式迁移，版本和全部内容须与来源包一致；新版 CLI 可通过 `--legacy-source <旧发布包目录>` 只读核对旧内容，保留原版本完成迁移，再单独 update。旧锁转为历史指针；旧自定义 AGENTS 不自动删除，旧 v1 受管绑定须明确协调。迁移不能夹带升级。

静态文件一致、宿主发现、模型实际行为分别报告。首次验证仅覆盖 Codex 项目路径；不能据此声称所有宿主自动生效。

## 工作区自有 Project Profile

Project Profile 使用显式 `project-profile-set` 和 `project-profile-remove`，但复用本生命周期的锁、审批摘要、journal、writer 与恢复路径。固定入口不进入 installation manifest，因此 package `init`、`update`、`remove` 不会创建、替换或删除它。候选评审、inspect、resource binding 与凭据边界见 [Project Profile](project-profile-contract.zh-CN.md)。Profile ready 不授权项目接入或任何 provider 副作用。

## 交叉评审后的恢复约束

恢复记录采用 1.2 格式，保存已完成操作、实际写入文件身份及原 POSIX 权限模式。创建 journal 前，捕获的各目标存在状态须与计划基线一致；不一致即拒绝，不开始任何计划中的项目操作。journal 与其临时及备份副本使用 0600，不受 umask 放宽；删除后回滚按记录恢复原模式。替换现有目标前会复验初始捕获的来源模式；准备恢复链接不会重定权限基线，外部权限变化会拒绝替换并保留当前目标。权限恢复不涵盖 ACL、owner/group 和扩展属性。旧 1.1 日志仍可凭完成身份移除新建文件；替换或删除的原有文件缺少原权限记录，要求人工核对归属与权限。替换后的当前模式不能证明原模式或特殊权限位，不推断任何权限回退值。相同内容不代表归本次操作所有：未开始的操作不回退，外部创建的文件保留并列入结果；已完成文件的身份或内容变化则阻止自动回退。写入后、完成记录落盘前中断的窗口需人工核对，旧候选无身份记录的日志不自动升级。

日志总量（包含全部进度记录预留）不得超过 4 MiB，超限在计划阶段和写入前拒绝，不扩大恢复系统。新受管块通过标记内 framing 注释声明两个前置 LF 和一个后置 LF 的所有权，摘要及提取同时核对分隔字节，反复接入/移除保持用户字节不变。旧普通块仍可读取，归属不明的空白不自动删除。未闭合的顶层代码围栏、HTML 注释及 script/pre/style/textarea 容器在只读计划阶段拒绝；处理指令（`<?` 到 `?>`）、声明（`<!` 后接大写字母，到 `>`）和 CDATA（`<![CDATA[` 到 `]]>`）同样须闭合。容器关闭标签同一行的后续注释或容器继续检查，被转义的 backtick 起点不能掩盖真实注释。共享的有界 code span 匹配遵守已支持的段落和块边界；块内跨行追踪关闭 backtick，避免将关闭符再次当作起点而掩盖后续真实注释。限定结构检查不代替完整 Markdown 解析，歧义结构须先协调。v1 与项目生命周期双向拒绝重复绑定，普通散文提及标记不作为实际绑定。漂移仍整体拒绝移除，不提供部分卸载。

有效安装发生漂移时仍属于轻量接入，但健康状态为 drift。操作锁和日志会阻止旧版绑定写入；即使 CLI 与安装版本不同，也检查旧受管文件旁的恢复证据。CLI 来源不完整时，doctor 仍保留项目观察和恢复摘要，并同时报告来源错误。

需要恢复不等于失去安装所有权：配置和安装清单仍完整有效时保留轻量接入身份，健康状态仍为 recovery-required。首次接入中断且没有完整有效清单时，不声称已接入。

恢复锁或日志不可读时，仍保留独立核验有效的安装身份，并阻止写入。项目生命周期的目录检查以每个目录 10,000 项为上限，超限报告观察错误，不进行无界扫描。

计划最多支持 520 个操作（包含元数据写入）。预览与应用使用同一校验；即使新旧安装各自满足 512 项清单上限，合并路径后的更新操作过多也会在预览时拒绝。

每次写入立即核验当前文件，在元数据提交和日志移除前统一复核已完成写入的文件身份，避免每步重复扫描全部历史目标；相同字节不能掩盖外部替换。没有安装元数据时，doctor 仍检查根目录和元数据目录的恢复残留，报告 recovery-required，但不声称已接入。

回滚保留本次恢复写入返回的文件身份，在恢复元数据及清理日志前复核；已安装和未安装项目均检查元数据目录的恢复残留。生命周期回归覆盖完整执行 520 操作的更新，耗时取决于文件系统和文件大小。

恢复预览时，若已开始操作的目标已变回原先的非空内容，自动回滚要求先核对所有权。相同字节无法区分外部恢复与再次中断的回滚；1.1 和 1.2 版日志不跨恢复尝试持久保存回滚身份，因此保留日志和当前文件，不猜测接管。原基线为文件不存在时不认领任何文件，仍可安全跳过。AGENTS.md 残留生命周期绑定而安装元数据缺失时，同样报告 recovery-required，不声称已接入或虚构恢复日志；重试接入前须核对残留绑定与元数据。
