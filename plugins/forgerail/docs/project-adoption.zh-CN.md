# 项目接入闭环（0.1.5）

本文面向 0.1.5，实际发布状态以 npm 和版本化 GitHub Release 为准。已发布 0.1.4 没有这些命令；安装 CLI 不会自动迁移旧快照，更新需明确授权。完整接口与恢复契约见 [英文说明](project-adoption.md)。

本轮只维护 ForgeRail 自身 Codex Skill 和 AGENTS 受管块；不管理第三方升级，不增加执行器或后台服务。目标项目不需要 package.json，CLI 本身仍需 Node.js 22+。

1. 用精确目标版本运行 `forgerail init --workspace <项目>`，获得只读计划。
2. Agent 展示差异，在用户已有接入授权内使用 `--apply <planSha256>` 执行，无须重复确认。摘要绑定内容，不代表批准。
3. 运行 `forgerail doctor --workspace <项目>`，离线检查来源与文件完整性。
4. 更新或移除分别使用 `update` / `remove`，同样先规划，再按摘要执行。

`.forgerail/config.json` 保存项目决定，`installation.json` 保存生成事实。目录存在不代表持久治理；不新增个人配置、父子自动合并或任务账本。整文件和受管块分别拥有；块外修改保留，块内或 Skill 漂移阻止覆盖/移除。移除不删除整个目录，也不卸载全局 CLI。

操作使用协作锁和临时恢复记录，安装清单最后写入。中断后用 `recover` 预览回退，再用 `--apply` 执行；目标出现外部修改就停止并保留。进程已退出的项目锁须按 doctor 给出的 lockDigest 单独释放。进程在单文件写入内部被杀死时可能留下锁或恢复副本，自动回退会拒绝，需要逐项核对，禁止批量删除恢复文件。

旧快照使用 `init --legacy-lock <docs下的来源锁>` 显式迁移，版本和全部内容须与来源包一致；新版 CLI 可通过 `--legacy-source <旧发布包目录>` 只读核对旧内容，保留原版本完成迁移，再单独 update。旧锁转为历史指针；旧自定义 AGENTS 不自动删除，旧 v1 受管绑定须明确协调。迁移不能夹带升级。

静态文件一致、宿主发现、模型实际行为分别报告。首次验证仅覆盖 Codex 项目路径；不能据此声称所有宿主自动生效。

## 交叉评审后的恢复约束

恢复记录采用 1.1 格式，保存已完成操作及实际写入文件身份。相同内容不代表归本次操作所有：未开始的操作不回退，外部创建的文件保留并列入结果；已完成文件的身份或内容变化则阻止自动回退。写入后、完成记录落盘前中断的窗口需人工核对，旧候选无身份记录的日志不自动升级。

日志总量（包含全部进度记录预留）不得超过 4 MiB，超限在计划阶段和写入前拒绝，不扩大恢复系统。受管标记外不新增分隔换行，反复接入/移除保持用户字节不变；旧候选留下且归属不明的空白不自动删除。v1 与项目生命周期双向拒绝重复绑定，普通散文提及标记不作为实际绑定。漂移仍整体拒绝移除，不提供部分卸载。
